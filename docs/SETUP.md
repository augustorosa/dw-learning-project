# Setup

What you need for each track, and how to wire up the connections. Do the core section
first. Only set up an optional track when you reach it.

## Core track

### Accounts

- **A Snowflake account** where you can use `ACCOUNTADMIN` at least once, for the
  bootstrap in BF-04. A free trial account is enough for the whole core track. If you are
  on a shared company account, read BF-03 before you create anything.
- Check that **DCM Projects** are available on your account. They were in preview when
  this project was written, so confirm in the Snowflake documentation before you plan
  around them.

### Local tools

| Tool | Used for | Check |
| --- | --- | --- |
| Python 3.10 or newer (the generator alone runs on 3.9) | the data generator, dbt | `python --version` |
| `dbt-snowflake` (dbt Core 1.8 or newer) | everything in Epics 3 to 5 | `dbt --version` |
| Snowflake CLI (`snow`), with the `dcm` commands | DCM plan and deploy, running SQL files | `snow --version`, `snow dcm --help` |
| git | version control | `git --version` |

A virtual environment keeps this tidy:

```bash
python -m venv .venv
source .venv/bin/activate
pip install dbt-snowflake snowflake-cli
```

The generator itself uses only the Python standard library.

### Snowflake CLI connection

Add a named connection in `~/.snowflake/config.toml` (or `connections.toml`, depending on
your CLI version). Use your own account identifier and user. Keep secrets out of the repo.

```toml
[connections.brindle]
account = "<your_account_identifier>"
user = "<your_user>"
password = "<your_pat>"   # a PAT works in place of a password
```

Then `snow connection test -c brindle` should succeed.

### dbt authentication

Use a **programmatic access token (PAT)**, not `authenticator: externalbrowser`. The
browser flow hangs on a prompt instead of failing, which makes any unattended run look
like it is running forever (GOTCHA M). The PAT goes in the `password:` field, read from an
environment variable so it never lands in git:

```yaml
# dbt/profiles.yml
brindle:
  target: dev
  outputs:
    dev:
      type: snowflake
      account: "<your_account_identifier>"
      user: "<your_user>"
      password: "{{ env_var('SNOWFLAKE_PAT') }}"
      role: brindle_transform_rl
      warehouse: brindle_transform_wh
      database: brindle_dev_int_db
      schema: int
      threads: 4
```

```bash
export SNOWFLAKE_PAT="<your_pat>"
cd dbt && dbt debug --profiles-dir .
```

Make sure the PAT is **not restricted** to a role other than `brindle_transform_rl`. A
restricted PAT authenticates fine and then fails on `USE ROLE` with an error that looks
like a privilege problem (GOTCHA M).

BF-70, `snowflake/bootstrap/plain_account.sql`, creates the warehouse, the three dev
databases, and `brindle_transform_rl` if you are not doing the DCM platform track.
BF-73 needs **dbt Projects on Snowflake** in the account, because the daily task runs
`EXECUTE DBT PROJECT`. Confirm that feature before you schedule the build.

### Cost

Every warehouse in this project is XSMALL with a 60-second auto-suspend. The whole core
track runs comfortably inside trial credits. Suspend or drop warehouses when you take a
break of more than a few days, and run the teardown in BF-56 when you finish.

## Optional: AWS source track

- An AWS account with rights to create a security group, a DB subnet group and an RDS
  instance, plus the `aws` CLI and `psql`.
- A VPC with subnets in **two availability zones**, even though the instance is
  single-AZ (GOTCHA L). Check this first.
- The RDS instance is the one thing in this project with a standing cost. Use the
  smallest instance class and tear it down when you are not using it.
- Fivetran (BF-14) is optional on top of that, and needs a Fivetran account.

## Optional: AI agent track

- Cortex Agents and Snowflake Intelligence must be available in your Snowflake region.
  Check the Snowflake documentation for current region availability before starting
  Epic 7.
- The agent is created in `snowflake_intelligence.agents`, which needs the privileges
  described in the Snowflake documentation for your account.

## Optional: NetSuite track

Nothing extra. The NetSuite data ships as CSVs in `data/csv/netsuite/`, generated by
`data/generate_netsuite.py`, and loads into the same raw database with
`snowflake/raw/load_netsuite_from_csv.sql`. You do not need a NetSuite or Fivetran
account.

## Optional: Sigma track

- A Sigma account with an API client ID and secret, in a `sigma/.env` file that stays out
  of git.
- Your Sigma **API base URL**. It depends on your Sigma organization's cloud and region,
  and you cannot work it out from the credentials. A wrong one returns an error that looks
  like a bad token (GOTCHA J).
- A key pair for the Sigma service user, with the private key under `keys/` (gitignored).
